## 1. Pre-flight — do this before any `git add`

**`evaluation/logs/` is 42 MB across 286 files**, one of them a single 42 MB log. It is workload stdout,
regenerated by any run, and must never enter history — once committed it is permanent.

Append to `.gitignore`:

```gitignore
# Evaluation run artifacts — regenerated by evaluation/run.sh, never source
evaluation/logs/
evaluation/__pycache__/
evaluation/phases.jsonl
evaluation/report.json
evaluation/report.md
```

Then **verify before trusting it**:

```bash
cd .worktrees/feature-monitoring-ui
git check-ignore -q evaluation/logs/eval-hami-errors.log && echo ok || echo "STILL TRACKED"
git status --short | grep -c '^??'          # should drop from 37
git add -A --dry-run 2>/dev/null | grep -c evaluation/logs   # must be 0
```

### 1.1 Two judgement calls that are yours, not mine

| Item | Size | The trade |
|---|---|---|
| `docs-internal/front-end-design/*.png` | **4.0 MB** | They are the design reference [13](13-ui-visual-design.md) cites by name. Committing puts 4 MB in history permanently; not committing leaves the spec referring to files nobody else can see |
| `evaluation/phases.jsonl` + `report.md` | ~440 KB | Ignored above as generated. But they are the **evidence** for [14 §7–8](14-metric-evaluation.md)'s claims. If you want the results reproducible-by-reading rather than reproducible-by-rerunning, commit `report.md` and `phases.jsonl` and drop those two ignore lines |

My recommendation: **commit the PNGs** (a spec citing invisible files is a broken spec, and 4 MB is a
one-time cost), and **commit `report.md` but not `report.json` or the logs** — the Markdown is the readable
evidence, the JSON is a 427 KB machine artifact, and the logs are noise.

### 1.2 What the audit found clean

- **Site-specific values are already the repo's convention.** The node IP `192.168.6.123` appears in 5

## 6. Phase E — cleanup, only once master is verified

```bash
git worktree remove .worktrees/phase-0-backend
git worktree remove .worktrees/phase-1-dcgm
git worktree remove .worktrees/phase-2-nvml
git worktree remove .worktrees/phase-3-ebpf
git worktree remove .worktrees/phase-4-mig
git worktree remove .worktrees/feature-monitoring-ui
git branch -d phase-0-backend phase-1-dcgm phase-2-nvml phase-3-ebpf phase-4-mig feature-monitoring-ui
```

`git branch -d` (lowercase) refuses to delete anything not fully merged — keep it as the safety net and do
**not** reach for `-D` if it complains. A refusal means something is unmerged, which is information.

There is **no remote** (`git remote -v` is empty), so nothing is pushed and every step above is locally
reversible with `git reset --hard` until you add one.

## 7. Commit message conventions

From the project's CLAUDE.md, and matching the 44 existing commits:

- **No AI co-author trailers.** No `Co-Authored-By`, no `assisted-by`.
- Lower-case, imperative, no type prefix — the existing history reads
  `add the monitoring api service`, `rebuild the hardware dashboards on dcgm`.
- Brief and human-legible; the body carries the reasoning when a subject line cannot.
